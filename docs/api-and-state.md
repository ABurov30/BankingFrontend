# API And State Management

The frontend uses RTK Query for all server communication and Redux slices for
domain state that must be available outside a single query cache entry.

## API Base Layer

`src/shared/api/baseApi.ts` defines the shared RTK Query API instance.

Important behavior:

- `baseUrl` is `import.meta.env.VITE_API_URL ?? '/api'`.
- `getApiEndpointUrl(path)` builds browser navigation URLs from the same base
  for redirect-based flows such as Google OAuth.
- Requests include credentials with `credentials: 'include'`.
- Requests set `Accept: application/json` and `Content-Type:
application/json`.
- Endpoint modules inject their endpoints into `baseApi`.
- Tag types are `Auth`, `User`, `Account`, `Card`, `Transaction`,
  `Notification`, and `Health`.

## Unauthorized Recovery

The base query wraps `fetchBaseQuery` with authentication recovery.

When a request returns `401`:

1. The wrapper tries `POST /auth/refresh`, except for `/auth/login`,
   `/auth/logout`, and `/auth/refresh`.
2. Concurrent `401` responses share one refresh promise.
3. After a successful refresh, the original request is retried once.
4. If refresh fails, the app dispatches:
   - `accounts/clearAccounts`
   - `cards/clearCards`
   - `user/clearCurrentUser`
5. The browser redirects to `/login` unless it is already there.

When the current user profile request `GET /user/user-info` returns any
non-`2xx` response, the same session-expired cleanup and `/login` redirect run.
For `401`, the wrapper first tries refresh and redirects only if refresh fails
or the retried profile request still fails.

Do not bypass this base API for normal backend calls.

## Generated API Contracts

OpenAPI-generated types live in `src/shared/api/schema.ts`. This file is
generated by:

```bash
npm run api:types
```

Do not edit `schema.ts` manually. Project-facing aliases live in
`src/shared/api/types.ts`. Runtime enum constants live in
`src/shared/api/enums.ts` and should be used whenever UI logic needs real enum
values.

Current frontend enum domains:

- `AccountCurrency`: `USD`, `EUR`, `CNY`, `GBP`
- `AccountType`: `CHECKING`, `SAVINGS`
- `AccountStatus`: `ACTIVE`, `FROZEN`, `CLOSED`
- `AuthUserStatus`: `ACTIVE`, `BLOCKED`, `FORGET_PASSWORD`, `PENDING`
- `Role`: `USER`, `MANAGER`, `ADMIN`
- `CardStatus`: `ACTIVE`, `BLOCKED`, `FROZEN`, `EXPIRED`
- `UserProfileStatus`: `ACTIVE`, `BLOCKED`, `PENDING`

## Endpoint Modules

`authApi.ts` owns authentication and manager/admin auth endpoints:

- Login, Google OAuth login redirect, logout, refresh, signup, user
  verification.
- Password change.
- Manager block/unlock/verify user.
- Admin role changes.
- Manager user-list optimistic status patches.

`userApi.ts` owns user profile reads and recipient lookup:

- Current user info.
- Social sign-in accounts from the auth/user wrapper are normalized into the
  current `UserInfo` model.
- Manager all-users list.
- Manager single-user details.
- User lookup by email with accounts-with-cards for external transfers.
- Normalization from backend auth/user response shape into `UserInfo`.

`accountApi.ts` owns account operations:

- Create account.
- Top up and withdraw.
- Freeze and unfreeze.
- Get current user's accounts with cards.
- Get all accounts with cards for manager flows.

`cardApi.ts` owns card operations:

- Create card.
- Update card status and limits.

`transactionApi.ts` owns transaction operations:

- Get transactions by user ID.
- Create transfer transaction.

`CreateTransactionRequestDto` requires `sourceAccountId`, `sourceCardId`,
`targetAccountId`, `minorUnits`, `currency`, and `idempotencyKey`. Transfer
flows must resolve an active source card for the selected source account before
calling the mutation. The selected source card identifies the payment
instrument, but available funds are still calculated from the linked source
account. In the UI, `sourceAccountId` is derived from the selected source card
for transfer operations. Amount input is parsed through
`src/lib/moneyAmount.ts`: masked values such as `00.20`, `00.02`, `20.00`,
and `02.00` are sent to transaction creation as integer `minorUnits` values
`20`, `2`, `2000`, and `200`. Top-up and withdraw also send integer
`minorUnits` to the account endpoints.

`notificationApi.ts` owns notification operations:

- Get notifications.
- Mark notifications as read.
- Update notification query cache from websocket events.

`healthApi.ts` owns admin service health checks. It fans out to health
endpoints for account, auth, card, notification, transaction, and user
services, then returns a service-keyed result map.

## Redux State Ownership

The app intentionally stores `user`, `accounts`, and `cards` in Redux slices
instead of relying only on RTK Query cache.

Ownership:

- `src/features/user/userSlice.ts` owns the current authenticated user.
- `src/features/accounts/accountsSlice.ts` owns account snapshots with nested
  cards.
- `src/features/cards/cardsSlice.ts` owns flattened card-with-account rows.
- `src/features/app/appSlice.ts` owns theme state.
- `src/features/rightPanel/rightPanelSlice.ts` owns the right-panel content
  key.
- `src/features/toast/toastSlice.ts` owns transient toast messages.

## Account And Card Synchronization

`src/features/accounts/syncAccounts.ts` is the synchronization boundary for
account and card projections.

- `syncAccountsSnapshot(dispatch, accounts)` writes a fresh account snapshot to
  `accounts` and derives the flattened `cards` slice.
- `syncAccountUpdate(dispatch, account)` patches the account slice and updates
  account data nested inside card rows.
- `syncCardUpdate(dispatch, card)` patches nested cards inside the accounts
  slice.

Account queries should synchronize both `accounts` and `cards` after successful
fetches. Card updates should synchronize both the `cards` slice and nested
cards inside the `accounts` slice.

## Mutation Refresh Rules

Some mutations return enough data for local patching. Others invalidate and
force a snapshot refresh.

- Top-up and withdraw use returned account data through `syncAccountUpdate`.
- Card update uses returned card data through `syncCardUpdate` and
  `cardsSlice.updateCard`.
- Create account invalidates account state and refetches current accounts when
  the owner user ID is known.
- Freeze/unfreeze invalidates account state and refetches current accounts.
- Create transaction invalidates account/card/transaction tags and refetches
  current accounts.
- Create card invalidates account/card data and marks account state stale.

## Notifications WebSocket

`src/features/notifications/useNotificationsWebSocket.ts` connects to STOMP
when the current user has an `authUserId`.

Default websocket URL:

```text
ws(s)://<current-host>/api/ws
```

Override with `VITE_NOTIFICATIONS_WS_URL`.

The hook:

- Subscribes to `/user/queue/notifications`.
- Parses JSON and plain text events.
- De-duplicates events by event ID.
- Invalidates and refetches account/card state for account, card, and
  transaction notification types that can change balances, account status, card
  status, or card limit usage.
- Invalidates and refetches current user transactions for transaction status
  notification types.
- Adds live notifications to the RTK Query notification cache.
- Shows a success toast for received notifications.

## Transaction Status WebSocket

`src/pages/transactions/components/TransactionStatusDialog.tsx` opens a STOMP
connection while the transaction tracking modal is mounted.

Default websocket URL:

```text
ws(s)://<current-host>/api/ws
```

Override with `VITE_TRANSACTIONS_WS_URL`. If it is not set, the dialog falls
back to `VITE_NOTIFICATIONS_WS_URL`.

The dialog subscribes to:

```text
/user/queue/transactions/{transactionId}
```

Incoming JSON payloads are merged into the selected transaction snapshot so the
modal can show live status, `minorUnits`, currency, source account, and target
account updates.

## Data Formatting Rules

Money formatting must use currency symbol plus amount:

```text
$ 0.00
€ 0.00
```

Keep API/runtime currency enum values as `USD`, `EUR`, `CNY`, and `GBP`, but
render user-facing currency labels as symbols.

Use `src/lib/formatMoney.ts`, `src/lib/moneyAmount.ts`,
`src/lib/cardLimits.ts`, and `src/lib/getAvailableFunds.ts` for shared money
formatting, amount parsing, card-limit unit conversion, and balance
calculations.

## Card Limit Usage Fields

Card response DTOs include:

- `dailyLimit`
- `monthlyLimit`
- `spendDailyLimit`
- `spendMonthlyLimit`

The card limits UI uses the spent fields to calculate usage progress against
the configured daily and monthly limits. User-facing limit values are displayed
in the major currency units returned by `/account/accounts/{ownerUserId}`.
Card limit edit inputs use the shared minor-unit money mask from
`src/lib/moneyAmount.ts`, and card update requests send integer minor units.
Use `src/lib/cardLimits.ts` when preserving existing card limits for status
updates because the update endpoint still accepts minor-unit request fields.
